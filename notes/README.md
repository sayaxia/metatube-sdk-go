# notes/ — 每轮发布说明（唯一来源）

每个发布版本对应**一个**文件：`notes/<MINOR>.<PATCH去掉>.md`，即 `v4.1` → `notes/4.1.md`。

规则：

1. **只写本轮改动。** 不复制历史版本的条目，不写"沿袭上版"之类的话。
2. **面向使用者。** 写清"用户能看到什么变化"，不要罗列 commit 或内部重构细节。
3. **一条一行。** 用 `- **标题**：一句话说明` 的格式。
4. CI（`release.yml`）在打 tag 时会校验本文件存在，缺失直接失败 —— 这样不会出现
   "填了上个版本的说明"或"完全没写"的 Release。
5. `scripts/version.sh release` 在文件缺失时会生成一份空模板并中止，填完重跑即可。

文件正文会被原样拼进 GitHub Release 的「本轮改动」小节，标题、资产表、GHCR 地址由 CI 自动补。
